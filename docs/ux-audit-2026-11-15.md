# GilaMonster UX audit, 2026-11-15 (K665)

The owner asked for "a UX pass done on the UI so we can start making major improvements". This is that pass. Nothing here has been changed yet: the Head of Software ranks it with Simon first.

**How it was done.** Every page and dialog was drawn with the DEBUG snapshot (`GILAMONSTER_SNAPSHOT`) in light and dark, 26 screens each, against a throwaway stopped server with no plugins, players or backups. Then each was read against `ops/rules/mac-apps.md` (D211 and the accessibility list) and the code behind it.

**Limits of this pass.** The snapshot draws page content only, so the toolbar (Start, Stop, Restart, Issues) and the menu bar weren't seen. The snapshot window is never the key window, so the sidebar may look dimmer than it does in use. Only empty states were seen: a busy server with 40 plugins and real players will show different problems. VoiceOver and keyboard focus weren't tried by hand.

## Ranked findings

Rank is how much it gets in the way, times how often. Effort: S under an hour, M a day or less, L more.

### 1. Overview doesn't say what to do next (M)

Eight cards of equal weight, in a two-column grid. Start lives only in the toolbar. The second-largest text on the page is the server's folder path, truncated in the middle. When something needs attention (an update waiting, no backup yet, automatic backups off) it's a small number in a card, at the same size as everything else.

Proposal: replace the path with a one-line status ("Stopped. Last backup: none yet."), put Start and the one most useful next step at the top, and let cards that need attention rise above the rest. The path moves into the server menu or Show in Finder's tooltip.

### 2. The Issues panel takes a quarter of every page, even when empty (S)

About 300 points wide on every page, saying "Nothing to report". On Players and Configs, which have their own list column, the real content is squeezed into the middle third.

Proposal: hide the panel when there are no open issues, and show the count on the toolbar button (it already has an `accessibilityValue`). Open it automatically when a new issue arrives, as now.

### 3. Disabled buttons don't say why (S to M)

Seen on Overview (Can Friends Connect?, Check, Check From Outside), Backups (Test Latest Backup, When, How often), Software (Check Plugins), Resource Packs (Check for Updates, Add Link) and Cleanup (Move 0 Selected Aside). A grey button gives no hint of what would turn it on. Of 116 `.disabled(` calls, most have no `.help` beside them.

Proposal: every disabled control gets a reason, as a tooltip and in its VoiceOver hint ("Start the server first", "Add a connection first"). Where the reason is a setting on the same card, hide the dependent controls instead (When and How often under an unticked "Back up automatically").

### 4. Fields labelled only by their placeholder (S)

Add a Plugin (the project field shows "luckperms"), Add a Server (name field "My Server"), Resource Packs (link field), Allowlist (username field), Launch (Extra JVM arguments has a label, but its example looks like a value). Once someone types, the label is gone, and "luckperms" reads as a value already filled in. This also fails the mac-apps rule that every control is named for VoiceOver unless each has an `accessibilityLabel`.

Proposal: a visible label on each, and examples moved to the hint line below ("such as luckperms").

### 5. Add Plugin's Add button works with an empty project (S, bug)

`PluginSource.isSet` is `self != .none`, so `.modrinth(project: "")` counts as set and Add is enabled the moment the dialog opens. The same check gates Check Now and "Not checked yet" on the Plugins page.

Proposal: an `isComplete` that also needs the project, repository, job address or URL, used by the dialog and the page. Small enough to fix now, with a check.

### 6. Too many buttons in a row on Software and Overview (M)

Software's Change version card has five actions (Check Plugins, Try on a Test Copy, Install…, Rehearse in the Lab, Check with Preflight), wrapping onto two lines, with the primary colour on the second. Overview's Server icon card has three for a rarely used feature.

Proposal: one primary action per card. On Software, Install… is the action, and the safer paths (test copy, Lab, Preflight) become a "Try it first" menu beside it, with Try on a Test Copy as its default. Server icon moves to the server menu or Settings.

### 7. Backups is one very long page (M)

Drill, schedule, keeping rules, storage order and drive caps run to about three screens. The schedule hides its numbers inside sentences with tiny steppers ("Once the server's been empty 10 minutes ⇕"), which are small targets and slow to change by more than a few steps.

Proposal: the backup list and Back Up Now on top, where people come to restore. Then two folded sections, Schedule and Storage. Steppers become number fields with steppers, so 60 can be typed.

### 8. Two similar names in the sidebar: Plugin Links and Plugins (S)

"Plugin Links" is the page players sign in to see. Its name says nothing about players, and it sits next to Plugins.

Proposal: rename to "Player Page" and move it under People, or make it a tab on Plugins. A naming question for the owner.

### 9. Plugin Links offers Start Serving when nobody could sign in (S)

With WelcomeWagon missing and online-mode off, the page shows two warnings and then a bright primary Start Serving button. Starting it serves a page that refuses everyone.

Proposal: disable it with the reason (finding 3), or keep it enabled but change it to plain style with "Nobody can sign in yet" beside it.

### 10. Empty states that leave a big blank (S)

Console is a large empty pane while stopped; only the command bar says why. Players gives a third of the width to "No players yet". History says "Zero KB" for worlds and backups, where the world exists and has a size.

Proposal: Console says "The server is stopped. Its output appears here when it starts." Players collapses its list column when there's nobody. History says "None yet" for backups and shows the world's real size (check whether "Zero KB" is a bug in the size read).

### 11. Configs uses three columns for one file (S)

The file list column holds a single entry, "Server properties", on a server with no plugin configs.

Proposal: hide the list column when there's one file.

### 12. Settings doesn't use the app's palette (S to M, check first)

The Settings dialog draws in system grey, with grey switches, where every other screen uses GilaMonster's greens. It may be the snapshot's non-key window; check in the running app before changing anything.

### 13. Launch's memory sliders are hard to set (S)

The sliders run from 0 to this Mac's 64 GB, so 4 GB sits at the far left and the useful range is a few pixels wide. The number field beside them works.

Proposal: snap to sensible steps (1, 2, 4, 6, 8, 12, 16 GB), or drop the slider and keep the field with Quick size's presets.

### 14. Small wording

- "Move 0 Selected Aside" reads oddly; say "Move Selected Aside" and disable it with a reason.
- Overview's Issues card has a Hide Panel button, which belongs on the panel.
- "Can Friends Connect?" as a button label is good; the same tone could replace "Check" on Connections ("Check Connections").

## What's already good

- Colour contrast is checked by CI across every pair, four appearances and each colour-vision simulation, and the source badges added today joined that check.
- Copy is plain and specific almost everywhere ("Nothing is deleted: items move beside your backups").
- Status badges pair icon, word and colour, so none rely on colour alone.
- Dangerous actions explain themselves before they happen (backup drill, cleanup, test copies).

## Not yet checked

- Keyboard-only use of each page, focus order and visible focus.
- VoiceOver reading each page.
- Layout at small window widths, and with larger text.
- The menu bar and toolbar against D211 (covered by checks, not seen here).
- A busy server: long plugin tables, many issues, a running console.

## Suggested order

1. Quick wins in one PR: findings 2, 3, 4, 5, 9, 10, 11, 14 (S each).
2. Overview redesign (1), with a mockup to the owner first.
3. Software and Backups layout (6, 7).
4. A hands-on keyboard and VoiceOver pass on a running throwaway server.
5. Naming (8) waits for the owner.
