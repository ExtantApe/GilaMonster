## Unreleased

- **A new look: the desert base, calmed down (K786).** The owner's pick, 2026-11-25: "B: desert base, calmed down". The 17-row sidebar is now a basalt **spine** with the lizard, the server switcher and five section beads (Home, Server, Content, People, Upkeep), each with its word and a badge for what's waiting there. ## 0.5.0 (2026-11-24)

The full-review release. Tested with the full check suite (3757 checks, 98 of them new), the heavy-data overflow check (`--snapshot`, 12 more checks, passed) and, for layout, pictures of every page drawn off screen from made-up servers, normal and heavy, in Bold and Quiet, light and dark. VoiceOver, Voice Control and the keyboard were not run by hand: the accessibility changes come from a code review and are checked only where a check can reach them (the rules, not the speech). The ask panel's focus and the announcements are not tested.

- **Long lists split up.** The allowlist gets a **Search names** field past 12 entries and shows the first 25 matches, then **Show All (N)**. Turned-away shows 5, then Show More. Worlds are grouped into **Loaded (N)** and a collapsed **Not loaded (N)**, with a filter past 10 worlds. Loaded means the server loads it at startup (its own worlds, and Multiverse worlds set to autoload); GilaMonster doesn't ask the running server, so a world unloaded by hand still shows as Loaded. Changes are grouped by kind with counts, 8 per group, then Show More. Plugin Links shows 10 recent sign-ins, then Show More, and counts who is signed in. Sheriff and WelcomeWagon profiles and questions are two cards, six showing, and several settings problems share one callout with three showing.
- **Long names stay on one line.** Names on allowlist, world, change, invite and player rows keep one line, cut in the middle, with the whole name on hover. Facts, such as those on the Performance card, stack label over value when the card is narrower than about 280 pt. A long error used as a callout title keeps its first sentence; the rest goes under Show Details.
- **The session ask panel can take the keyboard.** Opened from the menu bar or a notification click, it becomes the key window and focus lands on the first Deny, which is also what Return does. A new ask that arrives by itself still doesn't take focus from whatever you're typing; VoiceOver announces it. **Need More Time** adds a minute to an ask, three times at most, and allows nothing. The 0.8 second click guard now applies to pointer clicks only, so a key press isn't held up.
- **VoiceOver announcements** for notices, warnings, problems and done messages that appear after a page has opened, and for a job starting and ending. The first second of a page stays quiet, because VoiceOver reads the page then.
- **Text size** for the console and the file editor, Command-plus and Command-minus. Typed commands show **Command:** ahead of the text, so they differ from the app's lines by words as well as color. Both text views have accessibility labels.
- **Tooltips reach VoiceOver** as hints. Plugin update badges say **Update 1.2.3**. The backup storage Remove button's spoken name starts with Remove. Charts have a descriptor VoiceOver can explore, and the players chart has a solid line over its wash. Callout borders are solid, the icon picker's border meets the control outline contrast, sheet titles are headings, and the first field in a sheet has the cursor. The Players list shows the word online.
- **Stop is Control-Command-period** (it was Command-period). A theme change redraws the page content, not the sheets or the window. The page's own state resets when it does, so text typed into a field on that page is lost; Settings is a separate window, so this only happens when the theme is changed there. Callouts aren't announced in the moments after a theme change. The Lab's Optional label uses the caption size.
- **The ask panel is reachable from the keyboard.** Window menu, **Requests Waiting for You**, Option-Command-R. Escape denies the first waiting ask. Each allow, deny or lapse is announced. **Need More Time** shows how many are left, announces "One minute added, N left", moves the reminder to the new deadline, and says why it's disabled after the third. A pointer click dropped by the guard dims the buttons for a moment and is announced. The cap of three is a decision, recorded in `docs/ux-audit.md`.
- **Fields and link buttons.** Search names, Filter worlds, Filter lines, Username, Address and Port use a field with the control outline (3:1) and a muted placeholder. Show Details, Show More, Show Fewer, Show All and Need More Time are ink, underlined, with a chevron or plus, so color isn't the only cue; ink on each background they sit on is in the palette checks. Callouts are read as "Warning: ..." and so on. Tooltips are hints only where they add words.
- **No-overflow check.** `gilamonster-check --snapshot` deletes old reports, draws every page with the heavy fixture in four looks, needs every page drawn and none wider than its window, and proves the measure by drawing every page too wide on purpose and needing each one reported. The heavy fixture has 30 waiting changes, and its pictures are tall enough to show Show All, Show More and the group headings. `scripts/snapshot-fixtures.sh` makes the made-up servers (normal and heavy) and keeps the pictures where you point it.
- Left alone: the window's minimum width is still 1120 pt.

## 0.3.0 (2026-11-23)

Tested with the checks below, against made-up servers and real Paper servers started for the tests. Allow for today and the busy refusal haven't been seen on screen or used with a real server yet.

- **A session's start, stop or restart while the server is busy is refused with the reason (K722).** A start sent during a backup came back as ok with the server still stopped, and nothing was asked, because Start does nothing while a backup, a change or another start holds the server. Now it's refused, "A backup is in progress on <server>, so nothing was changed", before anyone is asked, and again after the answer if a job started meanwhile. Tested: a check holds the server busy and sends a start. Not tested: during a real backup.
- **Allow for today on a session's prompt (K721).** Next to Allow, one click allows that kind of action on every server until midnight, Mac time. Allowing a stop covers starts, stops and restarts everywhere today. Publishing, marking Packmule updated, pack serving and pack addresses are each their own kind. It never covers removing a pack address, naming a player, or anything that deletes, restores or resets a world. Each action that goes ahead this way first checks nobody is on that server: with someone online it asks as usual, and when GilaMonster can't tell, it refuses. Each one shows a notice, writes a line to the server's log and goes in the record. **Revoke Today's Allows** in the menu bar ends them all, and quitting GilaMonster does too. Grants live only in memory, and no session call can make or extend one. The Mac notification for an ask has the same button, and both say how far it reaches. After a security review: who's online also counts the server's login and disconnect lines, so a player hidden by a vanish plugin counts; a revoke during the online check makes it ask; the clock set back can't stretch a grant; midnight follows a time zone change; what went ahead is listed under the menu bar leaf too, in case notifications are held back; a click in the moment after the rows shift is ignored; and a recipe name with a line break is refused. Tested: 8 new check groups (706 checks in the quick set pass), covering midnight, a second server covered and another kind not, revoke, players online, refusing when unsure, and that only a click on a waiting ask makes a grant. Not tested: the button, notice and menu item on screen, and a real start or stop through it.
- **The Overview leads with what to do next (K672, from the 2026-11-16 mockup).** Under the server's name, one line says how it is: "Stopped. Paper 26.3 build 253. No backup yet." or "Running for 2 hours. 3 players on. Last backup 40 minutes ago." **Needs you** then lists what wants attention, most urgent first, each with its button: no backup yet (Back Up Now), automatic backups off (Turn On), a backup drive near its cap or short of room for another backup (Open Backups), issues of error severity (Review), connections that need a look, plugin updates that fit (Review) and a server software update (Open Software). With nothing to do it says "Nothing needs you." **At a glance** keeps the cards below. Start, Stop and Restart are in the page header as well as the toolbar. The folder path (Copy Folder Path), the server icon and Rename moved to the ••• menu; the icon picker opens as a sheet. Tested: 14 new checks for which situations show which items, their order and wording, the Lab, and the status line; the full check suite. Not seen on screen yet, and the drive warning and connection item weren't triggered on a real drive or tunnel.
- **Servers no longer outlive GilaMonster, and a stop from outside stays stopped (K692).** On 2026-11-21 a server stopped from outside GilaMonster was restarted 10 seconds later, then left running when GilaMonster quit. Three changes:
  - **A stop made outside GilaMonster isn't a crash.** A SIGTERM from another tool, or a stop sent to the console another way, makes the server shut itself down and save, but it exits with code 143. GilaMonster now reads the server's own log: if it ran its shutdown ("Stopping server") with no crash in the log, the exit counts as a stop, isn't restarted, and the console and History say it was stopped from outside. A real crash also ends with "Stopping server", so any crash line in the log ("Encountered an unexpected exception", a freeze or a crash report) still counts as a crash.
  - **A killed GilaMonster stops its servers first.** A SIGTERM, SIGHUP or SIGINT to GilaMonster (killall, a script, Ctrl-C in a terminal) now stops every server with a save, as at a shutdown, before GilaMonster exits. Before, the app vanished and its servers ran on with nobody to stop them.
  - **Servers left over from before are part of quitting.** A server an earlier GilaMonster started and left running shows as running outside GilaMonster. Quitting now names it in the question and stops it with a save, using the same SIGTERM as its Stop It button. At a shutdown it's stopped without asking.
  Tested: all 3559 checks pass. That includes the stand-in server getting a real SIGTERM with restarts on: it was seen as stopped, was still stopped 12 seconds later, and the console said so. Not tested: a real Paper server, a signal sent to the running app, and the quit question with a left-over server.
- **Backups no longer leave the world unsaved (K691).** A running server pauses saving only while its files are cloned, which takes a moment on the Mac's disk. Saving is then turned back on, the server has to confirm it, and the backup is made from the clone. Before, saving stayed off for the whole backup, two hours for a big world, and a backup that never finished left it off. If the server doesn't confirm, GilaMonster asks once more, then shows an issue saying saving may still be off. Copies for upgrades and test copies resume the same way. Where a clone isn't possible (another file system, a world linked from another drive), the backup works as before, and saving is still resumed and confirmed however it ends. Tested: the checks, with a stand-in server that confirms and one that doesn't. Not tested on a real server.

- **Old Sheriff and WelcomeWagon list formats are no longer read** (K71). Every server runs Sheriff 0.5.0 and WelcomeWagon 0.6.1, so GilaMonster reads only the spec's `items` list: Sheriff 0.4's `attempts` list and WelcomeWagon 0.2.0's `invites` list are gone. Tested: all 3537 checks pass, with the stand-in plugins answering in the current format.
- **Drive-only backups never fall back to the Mac's disk** (D250, owner, 2026-11-21: every Minecraft backup goes to MCBackups, "and not WDSSD or the internal Mac drive"). With **Back up only to <drive>** on, a backup while that drive is missing is skipped and reported, however long it's been gone, and nothing is written to another drive or the Mac's disk. A full drive, or one at its backup cap, is skipped the same way. The 24-hour and 75 GB settings are gone. A saved setting from the old rule still reads, as drive-only, and any backups the old rule left on the Mac's disk stay listed until they're moved. Both servers already back up to MCBackups with the rule on. Tested: the rule (connected, and missing for 0 to 720 hours), an old saved setting, and a made-up server with a stand-in drive (missing, missing 72 hours with lots of room on the Mac, the drive returning, a full drive); all 3537 checks pass. Not tested: a real drive being unplugged, or the page on screen.
- **The build won't delete a running app.** `scripts/build-app.sh` deletes `dist/GilaMonster.app` before it builds. On 2026-11-17 that pulled the bundle out from under a running GilaMonster. Now the script refuses (exit 3) while anything runs from the target bundle, and says what is running. `--out DIR` builds somewhere else, such as `dist-next`. Tested: `scripts/test-build-guard.sh`, in CI, with a made-up bundle and a running stand-in. It checks the refusal, that nothing is touched, another folder, a new folder, and building after quitting. Also checked against the real running app.
- **Asks find you, even in a Focus.** On 2026-11-17 three session asks timed out with the owner at the Mac. The log showed the scheduled Sleep Focus holding back every GilaMonster notification, with no sound, and macOS turning time-sensitive down for a locally signed build. The ask window did open each time, but it was small, silent and stayed on the screen it first opened on. Now each ask opens the window at the top of the screen the pointer is on, plays a sound GilaMonster makes itself (a Focus doesn't mute it), and bounces the Dock icon until GilaMonster is brought forward. With a minute left, the sound plays again and the window moves to the pointer's screen again. The window shows a live countdown and sits above other floating windows. Tested: 9 checks for where the window opens (two side-by-side screens, a pointer on neither, a screen smaller than the window) and when the reminder plays. Not tested: the window and sound on screen.
- **Backups can go to one drive only** (owner, 2026-11-16). With **Back up only to <drive>** on (Backups page, shown when the backup folder is on an external drive), every backup goes to that drive and the storage list is passed over. While the drive is missing, each backup is skipped with a warning and nothing is written to the Mac's own disk. Once it's been missing 24 hours straight, backups go to `GilaMonster/fallback-backups` beside the servers, but only if 75 GB would still be free after the backup (the last backup of that kind plus 20%). Both numbers can be changed. Those backups are listed with where they are and flagged as an issue to move, and backups go back to the drive as soon as it's seen again. Separately, a backup to a folder on a drive that isn't mounted is now refused for every server, so a pulled drive can't turn into a folder on the Mac's disk. Tested: 26 checks with a made-up server and a stand-in drive (connected, missing under 24 hours, missing with too little room, missing with room, the drive returning, and an unmounted drive). Not tested: a real drive being unplugged, or the setting on screen.
- **Local builds can keep one identity.** `scripts/build-app.sh` signs with a self-signed `GilaMonster Local Signing` certificate when the login keychain has one, so a rebuilt app isn't asked for Keychain access and notifications again. Without it, and for release and CI builds, the signature stays ad hoc. Tested: the script parses. Not tested: a build signed with the certificate, which nobody has made yet.
- **A Keychain prompt can't hold up the launch.** After a rebuild, macOS can ask before letting GilaMonster read its session token. GilaMonster waited for that answer on the main thread, so on 2026-11-16 the window never opened and the Dock icon kept bouncing. The token is now read in the background after the window is up, kept in memory, and read again only when it's replaced. Settings says "Waiting for Keychain access" while macOS asks. Without a token, nothing listens. Tested: the session access checks with a throwaway keychain. Not tested: a real prompt on a rebuilt app.
- **The Lab has its own page** (Head of Design review, 2026-11-16). Each server has a Lab item under Server in the sidebar, with the explanation, the checks and saved copies in one place. Tick the checks to run and click **Run Checks**: they run in order, and a check still locked when its turn comes is skipped with the reason. **Keep a copy of the lab after the next run** is a checkbox, with its note field shown only when ticked, and **Keep This Lab** covers a run that's going. Each check is one row, with its details behind a chevron. A red light says what failed first and what to do next. The Software page keeps one line about the last run and an Open Lab link. Tested: 5 checks for Run Checks with a stand-in lab. Not tested: the page on screen.
- **Asks can't be missed** (K679). Each session ask now opens a small window with Allow and Deny that stays in front, and the menu bar leaf shows how many are waiting. The notification still goes out when macOS allows it. On 2026-11-16 two asks timed out unseen because macOS delivered them as nothing. Each ask now logs whether notifications were allowed, and in what style. Not tested: the window on screen.

Each slot takes only its type, and a world must be one of that server's. Patterns are refused for commands that change permissions, the allowlist, bans or the server. - **A backup cap for each drive** (D213), set on the Backups page under Space on each drive. Every server's GilaMonster backups on that drive count, including one still being written. ## 0.2.0

Tested against real Paper 26.x servers started for the tests, with made-up players, and with the real plugins named
below. Not yet tested by anyone running it on a server people play on. The new screens haven't been checked with a
keyboard and VoiceOver yet. Plugin commands and the Advisor are off until you turn them on.

**Opening it:** GilaMonster is unsigned, so macOS blocks the first launch. Allow it one of two ways:

- **System Settings:** try to open the app once, then go to System Settings > Privacy & Security, scroll down, click
  **Open Anyway**, and click **Open** when the warning comes back. Apple says to do this only for an app you trust.
- **Terminal:** `xattr -dr com.apple.quarantine "/Applications/GilaMonster.app"`

Players and sign-in:

- Add someone to the allowlist before they've ever joined, with their LuckPerms groups. Groups you haven't ticked are
  never offered, and you can mark pairs of groups that shouldn't be combined.
- With Usher installed, approving someone goes through Usher's profiles and its questions, and never around it. People
  the whitelist turned away are listed. Needs Plugin commands, which is off by default.
- With Latchkey, make six-character invites for one Minecraft name with Usher profiles, see the code once, and list or
  revoke them. With Latchkey 0.3, the card shows whether its lobby is on, and each player's sheet can sign them out of
  the web pages everywhere.
- A page listing your plugins for people on the server, and BlueMap's web map behind the same sign-in. Players sign
  in with `/signin` in the game, through Latchkey. Both are off by default.

Resource packs:

- See what each pack contributes, serve packs from this Mac with their own address per build, and serve an exact pack
  file unchanged. Serving comes back when the app opens.
- Leave out any song a pack lists in its `songs.json`, so Minecraft's own track plays.

Upgrades and the rest:

- Before an upgrade, check plugins with Preflight's own tool on a copy, and offer to switch off ones that won't start.
- Pick the server icon from a folder of choices in `server-icons/`.
- The Advisor, an optional page that asks Claude Code for suggestions about a server, using your own Claude account.
  It's off until you turn it on in Settings, each server has to be shared, and the first check asks before sending.
  Only recognised log lines, stack traces and a fixed list of settings are sent, with players and addresses replaced
  by code names. The list of who each code name stands for is sealed with a key in your Keychain. macOS asks for
  that key once, and again after each update until GilaMonster is signed. See `docs/ADVISOR-SECURITY.md`. Tested with
  made-up servers. It hasn't been run on a real server yet.

## 0.1.0

The first release. Tested against real Paper servers started for the tests, with made-up data. Not yet tested by
anyone running it on a server people play on.

- Runs a Minecraft Java server from a Mac app: console, CPU and memory, restart after a crash with a limit, and
  keeps the Mac awake while running.
- Finds the server software, version, memory and flags of an existing server, and keeps everything it adds in
  `.gilamonster/`.
- Keeps Paper, Folia, Purpur, Vanilla or your own jar current, with hashes checked.
- Updates plugins from Modrinth, Hangar, SpigotMC, GitHub Releases, Jenkins or any web address, skipping
  releases tagged for another Minecraft version.
- Settings forms generated from `server.properties`, Bukkit, Spigot, Paper and each plugin's config.
- The Lab, a practice server with bot players for rehearsing an upgrade before doing it for real.
- Resource pack recipes: version, rank, build and share packs.
- A plugin links page listing each plugin, its version and where to read about it. It replaces the wiki.
